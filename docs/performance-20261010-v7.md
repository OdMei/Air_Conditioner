## 本轮实现

### 人体框按新结果更新

原 `app_ui_process()` 将文本、诊断和人体框都绑定到 200 ms 更新周期，框最多约 5 Hz。现在通过 `vision.frame_id` 更新人体框，由 LVGL 显示周期处理刷新；相同帧不会重复修改位置，结果失效立即隐藏旧框，进入 DEBUG 强制首次更新。

标题保持 200 ms，详细诊断保持 1 s。详细诊断在触摸按住或滚动惯性期间继续冻结，原 LTDC/VBlank 缓冲交接和延迟 flush 逻辑保持有效。

这提升了结果跟随频率，不保证每个 30 FPS 相机帧都在 LCD 上同步呈现，也不把框刷新计为 AI 推理次数。

### M55 Helium 像素转换

新增 `app_ui_pixels.c/h`，每次转换四个像素，源数据使用 `memcpy` 加载到向量，避免对齐和严格别名假设；剩余 0～3 个像素使用标量尾部。Alpha 和 RGB 均保留原高四位，源行按部分绘制宽度推进，目标行按 LCD 宽度推进。

实际 ARM 编译器已生成向量加载、移位、掩码、或及半字存储；只用 q0～q3，无谓词指令。PC 和强制标量配置使用同一模块的标量分支。

工程中的 DMA2D 同时被 LCD BSP、RGBLCD 和 JPEG 使用。本轮没有接入额外 DMA2D 调用，因此无需增加共享 DMA 所有权、缓存边界和中止协议。

### YOLOv2 后处理

- 单类别的 softmax 数学上恒为 1，直接使用 objectness，省去每帧最多 245 次无意义的类别指数计算。
- 已排序的 greedy NMS 选满配置框数后清除余下候选并结束；后续候选不能影响已选结果。
- 跳过已经抑制的候选，不再为零分候选计算 IoU。
- 保留 v6 的候选数组边界修复；多类别分支继续原有 softmax。

**数值边界：**旧版 `exp(x) × (1/exp(x))` 在单类情况下可能产生一个浮点末位误差。阈值恰好相等时，新版可能保留旧版舍入后丢弃的框；相同 objectness 的排序也不再由类别 logits 的舍入差异区分。此行为有单独反例测试，不能宣称所有浮点边界逐位一致。

### 性能诊断

打开 DEBUG→DIAG，顶部新增 `PERF last64 | avg/p95/max us`，对应每个阶段最近最多 64 个样本；统计每秒更新，P95 为最邻近秩。不是固定 1 秒的数据窗口。

| 字段 | 含义 |
|---|---|
| InWait / OutWait | 成功获取输入/输出缓冲的等待时间；超时恢复不算正常样本 |
| NN | `LL_ATON_RT_Main` 调用墙钟时间，包含抢占、运行时和硬件等待 |
| PP | 后处理函数调用耗时 |
| ISP | ISP 更新调用耗时 |
| UI | 界面处理耗时，包含可能的前景缓冲等待 |
| DP | 一次显示线程循环，从初始快照锁等待至休眠前 |
| Frame | 采集完成到后处理完成的有效结果延迟，1 ms 粒度 |
| TouchGap | 两次输入扫描启动的间隔，1 ms 粒度 |

短阶段使用经初始化和增长验证的 DWT 周期计数；不清零 CYCCNT。使用实际 CPU 时钟换算，并核对毫秒时间。长间隔、不可用计数或偏差超过 2 ms 时回退到 HAL 毫秒时间。诊断中的 `Clock DWT` 表示可使用周期计数，部分样本仍可能回退；它不代表全部字段具有硬件微秒精度。

新增成功发布及无空闲输入缓冲丢帧计数。串口每秒增加独立、有长度限制的 `PERF` 行。空窗口和 PC 模拟不伪造硬件耗时。

采样使用独立 ThreadX 优先级继承互斥锁，锁内只记录或复制窗口，排序在锁外。没有在中断中获取性能互斥锁。显示线程大快照和日志行使用线程独占静态存储，为 LVGL 和诊断格式化保留栈空间。
