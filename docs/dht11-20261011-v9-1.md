# v9.1 DHT11 读取与状态显示修复

日期：2026-10-11。用户已确认外接DHT11，DATA接PG3，并反馈温湿度显示迟缓、大多显示“数据未更新”。基线v9已烧录并由用户确认新版页面、画面、人体框和触摸正常。

## 原因与改动

1. 原位采样在上升沿后68µs，靠近逻辑1高脉冲的结束位置；GPIO开销与抢占使余量不足。改为40µs。协议依据为奥松原厂[DHT11手册](https://download.kamami.pl/p1180541-Dokumentacja-DHT11.pdf)：0高电平约26～28µs、1约70µs。
2. 原失败重试间隔为4/8/16/32/60秒，而当前温度新鲜度仅6秒。改为每次请求完成后至少2000ms再次读取，失败也不延长或连续突发补采；AP3216C初始化后独立等待2秒再首次读取DHT。
3. 原单次失败立即清有效位，UI仅显示新鲜值，使“未读取”和“本次失败”都显示未更新。现在显示首次等待/失败、上次成功值及年龄、恢复正常或过期；旧值明确标为上次读数。

失败仍立即使温湿度控制有效性为0并刷新现有控制逻辑，不能用上次值继续授权制冷；成功时间和上次值只在成功时更新。历史曲线继续依赖有效位，旧读数不会作为新采样点。

## 时序与诊断

捕获期间保存/恢复BASEPRI，暂缓优先级≥8的中断和PendSV，保留SysTick4、摄像头/CSI7及红外0的中断响应。18ms拉低、校验及浮点转换均在捕获保护外；不修改全局时钟、TIM1预分频或微秒延时函数。已有PRIMASK/BASEPRI或ISR上下文的读取请求被拒绝，避免阻塞式起始延时挂死。

新增驱动诊断和HAL无关的UI快照：完整请求/成功/失败数、连续失败、最近尝试与成功时间、状态码、是否曾有成功样本。DIAG增加DHT11 PG3统计，UART每秒有界输出独立SENSOR行。

详细状态码：0未读、1成功、2参数、3上下文、4无响应、5响应超时、6数据高电平超时、7数据低电平超时、8校验和。详细面板E字段携带该状态数字，不能把成功状态1当作失败次数。

优先级较高的长中断仍可能破坏读取；8位校验和有碰撞，不能保证所有损坏帧都能识别。因此仍需要实板观察读取成功率、错误码、摄像头和触摸；这些不是主机波形测试可以代替的结果。
