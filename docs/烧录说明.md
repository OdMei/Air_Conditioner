## 2. 使用 STM32CubeProgrammer 烧录

烧录前先给本机 STM32CubeProgrammer 添加板级外部 Flash 加载器。工程自带文件为：

```text
External_Loader/MX25UM25645G_ATK-CNN647B/Binary/MX25UM25645G_ATK-CNN647B_ExtMemLoader.stldr
```

将该文件复制到实际运行的 CubeProgrammer 安装目录 `bin/ExternalLoader`，重新打开软件后，进入左侧 `EL / External loaders`，搜索 `ATK-CNN647B`，勾选对应加载器。仅复制文件不会自动勾选。右侧 `External loader` 应显示板级加载器，不能仍为 `-`。

2026-10-08 排查时，本机 GUI 运行目录为 `D:/ST/STM32CubeProgrammer`，已将工程加载器复制到其 `bin/ExternalLoader` 并验证内容一致。随后已通过另一安装中可用的 2.23 命令行程序，将原版三份 HEX 实际烧入 STM32N647 Rev B，并逐项通过读回校验。GUI 勾选仍需手动确认；更换电脑或打开另一份安装的软件，都需要重新确认此配置。

官方依据：[加载器配置](https://wiki.alientek.com/docs/Boards/STM32/DNN647/start-guide/start-development/setup-development-tools/stm32cubeprogrammer/)、[开发流程](https://wiki.alientek.com/docs/Boards/STM32/DNN647/start-guide/start-development/step-by-step/)。

1. 开发板断电后，将 BOOT0 接 GND、BOOT1 接 3.3V，进入 `Development boot`。使用外接 ST-LINK 连接板卡 SWD，给板卡上电，并将 ST-LINK 接电脑。
2. 关闭 CubeIDE 的运行或调试会话，避免 ST-LINK 被 GDB Server 占用。
3. 打开上述已添加加载器的 STM32CubeProgrammer，选择 **ST-LINK** 连接方式，并确认 `EL` 页面已勾选匹配加载器。
4. 先使用当前能识别芯片的连接配置。如仍断连，可在 `Development boot` 模式下尝试 **Hot plug**；使用 **Under Reset / Hardware reset** 需要实际连接 NRST。
5. 如果连接不稳定，将 SWD 频率降低到 `1000 kHz` 或更低。
6. 点击 **Connect**，确认能够读取到设备 ID `0x486` 或设备名称 `STM32N647`。
7. 正常下载使用相应扇区的自动擦除，无需先整片擦除。只有明确需要清空外部 Flash 时，才在加载器已选中的“擦除外部存储器”页面操作，并确保能恢复全部三个镜像。
8. 进入烧录页面，依次添加并烧录：
   - `fsbl.hex` 到 `0x70000000`
   - `appli.hex`，使用 HEX 文件内的地址
   - `network-data.hex`，使用 HEX 文件内的地址
9. 等待下载和校验都显示成功，再点击断开连接。
10. 开发板断电，将 BOOT0、BOOT1 都接 GND，进入 `Flash boot`，重新上电后观察界面。

HEX 文件通常自带地址，CubeProgrammer 显示的地址应与上表一致。不要把 `network-data.hex` 当作应用程序烧到 `0x70100400`。

## 3. 推荐烧录顺序

建议每次都按以下顺序操作：

```text
擦除旧外部 Flash（必要时）
        ↓
fsbl.hex       -> 0x70000000
appli.hex      -> 0x70100400
network-data.hex -> 0x70200000
        ↓
复位开发板
```

`FSBL` 负责启动外部 Flash 中的应用。只烧录 `appli.hex`，或者缺少 `network-data.hex`，都可能导致应用无法启动或无法进行 NPU 推理。

## 4. CubeIDE 直接 Run/Debug 的限制

CubeIDE 的 **Run** 或 **Debug** 通常只负责下载当前应用工程生成的镜像，不一定自动烧录 FSBL 和 `network-data.hex`。因此第一次运行或更换完整工程时，建议先用 CubeProgrammer 手动烧录三份镜像，再使用 CubeIDE 调试应用。

如果使用 CubeIDE 调试，确认：

- ST-LINK 没有被另一个 CubeProgrammer 或 GDB Server 占用。
- 调试配置中的端口与 GDB Server 一致。
- 开发板已上电，NRST 和 SWD 连接正常。
- 外部 Flash 中的 FSBL 没有被擦除。

## 5. 常见问题

### `localhost:61234: Connection timed out`

这通常表示 ST-LINK GDB Server 启动后无法保持目标连接并退出。依次检查：

- 关闭其他占用 ST-LINK 的程序。
- CubeProgrammer 改用 **Under Reset** 和 **Hardware reset**。
- 将 SWD 频率降到 `1000 kHz`。
- 确认 ST-LINK 的 NRST 已连接到开发板 NRST。
- 先用 CubeProgrammer 单独连接并读取设备 ID，再启动 CubeIDE。

### `Unable to get core ID` 或 `Cannot identify the device`

检查开发板供电、USB 线、SWD 线和复位状态。必要时按住开发板复位键，在 CubeProgrammer 点击连接后再释放复位键。连接后先核对板级加载器、镜像和地址，再按所需扇区下载，不默认整片擦除。

### `connection to device 0x486 is lost`

若先识别到设备，但在 `0x70100400` 或 `0x70200000` 下载开始即报“无法下载扇区[0]”，先检查右侧 `External loader` 是否仍为 `-`。这些地址位于外部 Flash，需要安装并勾选正点原子板级加载器。再检查 Development boot、ST-LINK 占用与 SWD 频率；不要仅凭连接丢失就先擦除芯片。

### LCD 不亮或没有检测结果

- 确认已经烧录 `fsbl.hex`、`appli.hex` 和 `network-data.hex`。
- 确认应用镜像地址从 `0x70100400` 开始。
- 检查摄像头型号和排线。
- 确认使用的是 `991_AI_People_Detection` 对应的模型数据。
- 本例程不要求 SD 卡；不要用 `43_Camera` 的 SD 卡依赖作为判断依据。

### 中文路径导致 post-build 失败

部分旧版 `postbuild.sh` 依赖 Git Bash 的 `find`、`readlink` 等命令，中文路径可能出现乱码或找不到目录。建议将工程复制到纯英文路径，例如：

```text
E:\STM32N6_ATK\Air_Conditioner
```

再重新导入 CubeIDE 工程并构建。
