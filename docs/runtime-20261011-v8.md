## 本轮改动

### 背景缓冲交接

新增无HAL依赖的 `app_bg_buffers.c/h`，用三个缓冲明确区分实际扫描front、等待VBlank的pending、正在采集的fill。替换原背景索引固定递增，使相机不再选择尚未由LTDC释放的旧front作为下一DMA目标。

帧完成后的顺序为：准备空闲目标 → DCMIPP改址成功并读回确认 → 提交刚完成的图像 → 观察 `Layer1.RCR.VBR` 清零才确认显示和释放旧front。全局LTDC中断、前景Layer2完成或超时都不能代替背景Layer1确认。

pending未完成或没有空闲槽时，相机继续使用自己拥有的fill，丢弃这一次背景显示提交，保持AI管线独立。HAL提交失败后候选保持隔离，后续重试同一地址；相机停机/恢复也保留LCD所有权。没有在相机ISR中等待VBlank、复制图像或读取外部RAM采样。

诊断九像素采样改为先固定已确认front，打开中断读取，再释放固定。即使采样期间发生VBlank与相机IRQ，也不会把被采样图像回收为DMA目标。

当前显示的是最近可提交的完整帧，取消原固定一帧的显示轮转延迟；人体框仍有推理/界面刷新延迟，不保证视频与AI结果严格逐帧同步，也没有新增FPS倍率承诺。

DEBUG→DIAG新增：

| 字段 | 含义 |
|---|---|
| `BG F` | 通过Layer1确认的背景帧编号 |
| `Show` | 确认显示次数 |
| `Drop` | 本次无法安全提交的背景帧数，独立于NPU输入丢帧 |
| `Pend` | 等待显示的槽与等待标志；槽255表示无pending |
| `BG Err` / `DMA` / `S` | LTDC提交失败、DMA改址失败和最后状态 |

串口每秒增加有长度限制的独立 `BG` 行。CFBAR字段仍是可读的影子寄存器；front索引与BG帧编号表示已确认所有权。

### 真实触摸驱动测试与修复

新增测试直接链接生产FT5206、GT9xxx驱动，只mock I2C/HAL边界。修复前21组中7组失败，修复后扩展为25组、全部通过：

- FT非法点数、抬起、保留事件、越界或传输失败不再留下旧的按下状态。
- 合法原点 `(0,0)`、DOWN、CONTACT事件可以正常产生触点。
- 首点无效时可以使用后续有效点作为主触点，完整报告读取完成后才提交坐标，避免半帧状态。
- FT/GT竖屏镜像使用 `WIDTH-1-raw` 并核对原始坐标边界；板端横屏的原有交换映射保持兼容。
- 验证0/1/最大触点、非法count、事务地址和长度、初始化识别、错误报告及释放；GT未ready时保留已有完整状态。

原app_touch恢复测试仍用于上层恢复，不再把该层stub当作底层驱动覆盖。过时的源码文本断言按新解析语义更新，其余启动、安全和共享总线约束保留。

### 诊断计数

I2C2的请求、成功和恢复计数采用极短的保存/恢复中断状态增量，避免同诊断槽计数在抢占中丢失。HAL事务、mutex等待、PE/STOP恢复操作均在临界区外；地址、事务预算及恢复策略保持现有行为。

新增生产代码测试验证同槽嵌套抢占、失败重试、恢复、回绕和中断状态保存。移除请求计数保护的临时负向变体被测试拒绝，说明测试能捕捉原问题。
