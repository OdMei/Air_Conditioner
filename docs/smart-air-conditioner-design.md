# N647 视觉感知与无网智控智能空调设计

## 1. 目标与范围

本项目基于正点原子 STM32N647 开发板，构建一个用于低压安全演示的智能空调控制系统。系统使用摄像头和 NPU 进行人体检测，结合温湿度、光照、红外、触摸和用户按键判断用户状态，通过 LVGL 提供调试界面和用户界面，并以四路隔离继电器控制模拟负载。

语音识别放在手机、电脑、局域网服务器或无线终端，N647 通过以太网或无线链路接收结构化命令。项目后续可以把已验证的检测模型替换为 YOLO11n，但模型迁移不应改变控制状态机和 UI 接口。

当前演示使用 5V/12V 风机、低压灯泡或继电器线圈。N647 只连接继电器模块的低压输入端，不直接连接市电。若未来控制 220V 风机或压缩机，必须增加合格的交流接触器、保险、漏保、热保护和硬件急停。

## 2. 总体架构

```text
摄像头 ────────> 991_AI_People_Detection 视觉管线
电容触摸 LCD ──> LVGL 双模式界面
DHT11/1-Wire ──> 温湿度采集
AP3216C ───────> 光照采集
红外接收 ──────> 遥控器命令
用户按键 ──────> 本地控制/紧急关闭
RS485 ─────────> Modbus 传感器/功率计
RS232 ─────────> 调试日志/维护
音频输入输出 ──> 语音扩展/播报
以太网/Wi-Fi ──> 语音命令与数据上传
                         ↓
                  状态融合与策略任务
                         ↓
                  空调控制状态机
                         ↓
                 四路继电器驱动模块
```

软件任务边界如下：

- AI 任务输出人数、人体框、置信度和运动信息。
- 传感器任务输出温度、湿度、光照和红外事件。
- 通信任务接收语音命令并发送状态快照。
- LVGL 任务读取只读数据快照并发送 UI 事件。
- 控制任务是继电器的唯一写入者，统一执行时序和保护规则。
- 日志任务记录状态变化、继电器动作、通信故障和能耗数据。

## 3. 官方例程与开发底座

开发顺序采用以下官方资料：

1. `Projects/99_Applications/991_AI_People_Detection`：主工程底座，已验证摄像头、NPU、LCD 和人体检测。
2. `Projects/27_Touch`：电容触摸驱动参考，资料中的 BSP 支持 FT5206 和 GT9xxx 系列。
3. `Projects/61_NetXDuo_TCP_Client`：以太网和 NetX Duo TCP 参考。
4. `Projects/30_DHT11`：温湿度采集。
5. `Projects/24_AP3216C`：光照采集。
6. `Projects/35_Sensor/352_IMX335`：摄像头底层初始化和显示参考。

`43_Camera` 不作为主工程起点，因为其中包含 SD 卡初始化、FatFs 挂载和 BMP 保存流程。`991_AI_People_Detection` 运行时需要同时烧录 `fsbl.hex`、`appli.hex` 和 `network-data.hex`，其中 `network-data.hex` 为 NPU 模型数据。

LVGL 不是当前正点原子例程的现成主界面，因此采用“保留 AI/摄像头管线，增加 LVGL 任务”的方式集成。摄像头画面优先放在 LTDC 独立层，LVGL 负责上层面板和控件；用户模式关闭摄像头层，调试模式打开摄像头层。

## 4. LCD 与触摸界面

### 调试模式

调试模式采用左侧摄像头、右侧信息面板的布局，显示：

- 摄像头画面、人体检测框和人数。
- AI 置信度、帧率和推理耗时。
- 温度、湿度和光照。
- 在场、无人、睡眠、手动等状态。
- 设定温度和控制目标。
- `Relay_Compressor`、`Relay_Fan`、`Relay_3`、`Relay_Aux` 状态。
- 以太网、Wi-Fi、RS485、传感器和故障状态。
- 继电器测试和诊断页面。

### 用户模式

用户模式隐藏摄像头和底层诊断数据，显示：

- 大号当前温度和湿度。
- 当前运行模式。
- 目标温度及加减按钮。
- 开关机、自动、制冷、睡眠和无人待机按钮。
- 风机状态。
- 语音、网络和故障图标。
- 四路负载的简化状态。

触摸输入通过 `27_Touch` 驱动适配到 LVGL `lv_indev`。LVGL 控件只产生事件，例如开机、设温和模式切换；事件进入控制队列后由控制状态机执行。调试模式通过设置页、长按屏幕、用户按键、红外组合键或维护命令进入，并设置超时或密码以减少误操作。

摄像头帧缓冲区和 LTDC 缓冲区使用外部 HyperRAM 时，需要处理 DCMIPP、LTDC 与 CPU 的 Cache 一致性。LVGL 使用局部绘制缓冲区，避免重复分配完整屏幕帧缓冲区。

## 5. 用户状态与控制策略

系统使用多源信息融合：

- **在场**：连续多帧检测到人体，并通过时间滞回确认。
- **无人**：连续 5～15 分钟没有检测到人体，关闭压缩机并进入待机。
- **睡眠**：夜间光照/RTC 条件成立、检测到人体且长时间低运动。
- **手动**：触摸、按键、红外或语音命令触发，在一段时间内优先于自动策略。
- **故障安全**：传感器异常、控制超时、看门狗复位或严重通信故障时关闭全部继电器。

第一版习惯建模采用按时段统计，记录有人概率、常用设定温度、睡眠时段、手动调温行为、负载运行时间和能耗。数据可以通过 RS485 功率计获取，并通过以太网上传；不依赖 SD 卡。时序预测作为后续扩展。

## 6. 四路继电器

| 通道 | 软件名称 | 当前用途 |
|---|---|---|
| 1 | `Relay_Compressor` | 压缩机模拟负载 |
| 2 | `Relay_Fan` | 低压风机 |
| 3 | `Relay_3` | 预留 |
| 4 | `Relay_Aux` | 通用备用负载 |

控制状态机强制执行以下规则：

- 制冷启动时先开风机，再延迟启动压缩机。
- 停止制冷时先关压缩机，风机延时运行后关闭。
- 压缩机设置最小开机时间和最小停机时间。
- 无人待机关闭压缩机，必要时保留短时风机运行。
- `Relay_Aux` 默认关闭，仅在明确命令或配置策略启用。
- 长按用户按键、故障和看门狗复位关闭全部输出。
- 继电器动作写入环形事件日志。

## 7. 通信与板载外设

### 语音与网络

语音识别在手机、电脑、局域网服务器或无线终端完成，N647 接收统一的结构化命令，例如：

```json
{"cmd":"set","power":1,"mode":"cool","target_temp":26}
```

通信层抽象为 `voice_transport`，以太网 TCP、Wi-Fi TCP 或无线串口模块使用同一命令解析层。第一阶段先完成以太网，后续可以接 ESP32、RTL8720 等无线模块。无线模块是否可直接连接，取决于实际模块的接口电平和协议；RS232 电平不能直接当作 MCU TTL UART 使用。

### RS485

RS485 优先用于 Modbus 温湿度、CO₂、功率计、电表或远程 I/O。功率数据用于能耗统计、节能效果对比和习惯建模。线路使用合适的隔离收发器、终端电阻和偏置设计。

### RS232

RS232 作为维护接口，输出 AI、传感器、状态机和继电器日志，并支持参数配置和故障诊断。

### 音频

音频输出用于播报“制冷开启”“进入睡眠模式”“无人待机”和故障提示。光纤音频可连接外部功放作为扩展。音频输入预留给后续本地唤醒词、环境声音检测或离线语音，不列入第一阶段必需功能。

### 其他接口

- 红外接收：接收空调遥控器开关、模式和温度命令。
- 1-Wire：连接 DS18B20 作为备用温度点。
- CAN：预留楼宇控制器或工业扩展。
- 用户按键：开关机、模式切换、温度调节、调试模式和紧急关闭。
- LED/蜂鸣器：显示网络、传感器、继电器和故障状态。

## 8. YOLO11n 迁移边界

先使用 `991_AI_People_Detection` 中已能运行的检测模型打通摄像头、状态融合、UI、通信和继电器控制。YOLO11n 迁移时需要完成量化、转换、ST Edge AI/Neural-ART 部署和后处理适配，只替换 AI 模型适配层，不修改 `ai_result`、状态融合和控制状态机接口。

## 9. 分阶段验收

1. `27_Touch` 触摸坐标和 LVGL 静态页面正常。
2. 调试模式显示摄像头、人数、温湿度、模式、设定温度和四路状态。
3. 用户模式能够通过触摸完成开关机、调温和模式切换。
4. 四路低压负载按时序运行，压缩机保护和紧急关闭有效。
5. 以太网命令可以改变目标状态并返回状态快照。
6. 红外、按键、RS232 日志和 RS485 功率计正常工作。
7. 音频提示能够反馈关键状态和故障。
8. 无人待机、睡眠节能、传感器故障和通信断开场景符合安全策略。
9. 替换 YOLO11n 后，UI 和控制逻辑无需改动。
