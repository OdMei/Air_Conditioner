# 项目深化与板载资源利用备忘

日期：2026-10-10。用途：保存用户要求记住的优化方向和新增硬件信息，供后续实施时读取。本文件记录建议与约束；没有接入 BH1750、修改固件或新增真实负载。

## 当前目标与硬件

- 主要目标：课程/毕业设计演示，功能完整、界面清楚、可重复验证、便于答辩。
- 用户现有：正点原子 N647 开发板、IMX335 摄像头、800×480 触摸 LCD，以及两个 BH1750 光照小球模块。
- 用户已确认两个 BH1750 有 ADDR 引脚或地址切换能力。具体模块型号、供电规格、上拉配置、实物连接器和是否已经接线尚未确认。
- 当前 v5 已烧录并完整回读验证。用户确认 DIAG 连续滑动约 20 秒正常，Touch READY IC2 Err0 Retry0 K0，AI 更新率 30.3 Hz、PP=0。长期稳定性和持续串口心跳仍待验证。
- 尚无外部继电器/空调/低压负载。现有输出是软件控制请求。
- DHT11/DS18B20 是板上的外接传感器接口，不是已确认拥有的温湿度传感器；虚拟温湿度不得显示为实测。

## 保留的深化主线

推荐题目方向：基于 STM32N6 的视觉区域占用感知与空调节能控制仿真系统。

1. 保存限量人体框、置信度和时间戳，显示推理有效视野。当前 224×224 推理管线与 800×480 显示管线分别裁剪，框坐标需经传感器坐标映射到 LCD，不能直接按两组分辨率缩放。
2. 轻量匿名跟踪、画面区域占用、驻留时间和热力图。轨迹 ID 不等于身份；图像区域不自动等于真实房间面积或人体物理距离。
3. 虚拟房间热模型，将真实人员感知与模拟温控闭环结合；比较持续制冷、固定温控和人员感知策略的温度偏差、请求时长、启停次数。
4. 时间线、固定场景回放和故障注入，共用现有控制逻辑；明确标注模拟/回放数据，不宣称实测节电率。
5. 可选进阶：举手/挥手交互、坐姿/站姿等姿态模型；暗光/低活动只作为休息候选，不能直接认定睡眠。
6. 可选系统扩展：已有电脑上的仪表台、自然语言/语音助手或大模型命令解释；先稳定通信，命令由板端验证，不替代现有控制保护。
7. 自建实验场景、检测准确率和决策延迟评测；更换模型后重新测内存与运行时间，不把当前约 30 Hz 更新率当作新模型性能承诺。

## 两个 BH1750 的推荐用途

建议一个放窗边/环境参考点，一个放工作区/实际使用位置，先同位置对照，再分开放置。也可分别放工作区和休息区。

- LCD 分别展示两路真实照度（lx）、有效性、数据年龄和趋势，不仅取平均值。
- 结合摄像头区域占用，判断“有人但所在区域偏暗”，提出照明请求/提示；当前没有灯具负载，可先用 LED 和屏幕演示请求。
- 利用两点照度差及时间变化提供自然采光/遮挡的辅助线索。两个光照值无法单独确定光源种类，也不能准确换算太阳辐射热负荷。
- LCD 自动背光可参考使用位置的照度，加入平滑、上下限和滞回，避免频繁闪变。
- 板载 AP3216C 继续提供独立环境/接近信息；其当前 ALS 原始计数与 BH1750 的 lx 不能直接平均比较，需要按配置转换或校准。

芯片级接口要点（模块以自身规格为准）：ADDR 低对应 7-bit 地址 0x23，高对应 0x5C；两模块地址不同可共用 SCL/SDA。HAL 传地址参数使用左移一位的 0x46/0xB8。默认高分辨率首次测量最长 180 ms，可考虑约 200–500 ms 采样，测量等待不占用总线互斥锁。BH1750 是命令写入/直接读取两字节结果，不按 AP3216C 的寄存器读法接入。

BH1750 芯片 VCC 工作范围为 2.4–3.6V。封装模块可能有稳压/上拉，应按模块规格核对供电，保证板端 I2C 逻辑兼容 3.3V；具体板卡连接器位置未核对前不提供未经验证的插针号。

## 板载资源分工

| 资源 | 建议角色 | 当前接入状态与条件 |
| --- | --- | --- |
| 摄像头/NPU/LCD | 视觉感知、区域配置、状态与曲线 | 基础已运行；框、跟踪、分区等尚待实现 |
| AP3216C + 两个 BH1750 | 板端环境感知、两点照度、区域融合 | AP3216C 已有驱动；BH1750 尚未接入 |
| ADC 电位器 | 演示模式改变室外温度/虚拟热负荷 | 数值标为模拟，不冒充温度传感器 |
| 用户 LED/蜂鸣器 | 控制请求反馈、健康提示 | 先核对 GPIO、极性和驱动；不能当作真实空调运行反馈 |
| EEPROM | 少量目标温度、模式、阈值、标定参数 | 当前使用 HAL I2C4；写忙轮询无界，需先改有界等待、错误回传和后台保存 |
| 板载 SD NAND | 事件日志、实验 CSV、少量回放资料 | 先接入文件系统；持续图像写入需单独验证吞吐，不先实现录像 |
| HyperRAM/NORFlash | 图像/AI 缓冲与程序模型存储 | 保留已有布局；日志不能覆盖固件或模型区 |
| USB UART/USB Device | PC 仪表、日志导出、配置 | UART 持续心跳待排查；USB CDC 是另需适配的可选路径 |
| 以太网 | 局域网状态页、数据上传/远程配置 | 接口存在，当前业务未接入网络；需要网络连接 |
| 音频接口 | 可选状态提示/外部音源分析 | Line 输入不等于内置麦克风；播放需要已有耳机/音箱等输出设备 |
| RS485/CAN/RS232/USB Host | 后续设备扩展与协议学习 | 有匹配外设/第二节点时再加入，接口本身不提供环境测量或设备执行 |

## 总线与实施顺序

候选传感器总线为当前 I2C4（源码 PE13=SCL、PE14=SDA）；实际引出连接器仍需原理图确认。AP3216C 地址 0x1E、EEPROM 地址 0x50 与两个 BH1750 不冲突。现有 AP3216C/EEPROM 均使用硬件 HAL I2C4，并非软件 bitbang；新增设备前先统一总线初始化、互斥、超时与健康快照。EEPROM 原驱动写忙轮询无界，应先修正，不能直接并入高优先级触摸线程。BH1750 测量等待与 EEPROM 保存放在后台服务中。相机/触摸的 I2C2 刚完成故障修复，不优先把新模块并到该链路。

源码/官方例程已核对的资源：ADC 电位器例程为 PF6/ADC1_INP15，当前应用没有 ADC 初始化；用户 LED 为 PG10/PE10，已经配置输出且低电平亮；蜂鸣器 BSP 为 PD3，当前尚未初始化或业务接入。AP3216C 驱动读取 IR/PS，但应用主要使用 ALS；PS 原始计数不能直接显示成厘米。这些 MCU 管脚信息不替代实物接口针序核对。

推荐顺序：

1. 核对实物模块/引脚，统一传感器总线，接入双 BH1750 并验证照度与失效恢复。
2. 加入自动背光、双点照度趋势；保存少量阈值和标定参数。
3. 检测框/轻量跟踪/区域占用与照度融合，形成“人在何处、那里是否明亮”的演示。
4. 用电位器驱动虚拟环境，补齐温控仿真、事件回放与策略对比。
5. 日志存储、PC 仪表/以太网；最后选择姿态/手势/自然语言扩展。
