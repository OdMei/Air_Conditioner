# 2026-10-09 软件优化说明

本轮对应毕设路线中的数据可信度、控制逻辑、界面和可重复演示。用户确认尚未接外部负载，因此四路状态表示软件控制请求；第一版应用已烧录并回读验证。实板触摸反馈后的修复、可收起诊断及独立 FPS 已再次烧录，最新记录见 [触摸与相机诊断](touch-camera-diagnostics-20261009.md)。

## 已实现

| 部分 | 新行为 |
| --- | --- |
| 数据健康 | AI／光照 3 秒、温湿度 6 秒无成功更新即过期；更新时间只在成功采样后更新。未知 AI 不冒充无人 |
| 人员确认 | 有人／无人变化需持续确认 1 秒。未知数据或控制调用断档中断连续无人计时 |
| 模式 | 智能自动／手动制冷；手动模式不执行人员自动睡眠、节能或关机 |
| 人工接管 | 手动开机重置无人计时，不继承已经饱和的 30 分钟计时；有人返回不会自行重开电源 |
| 温度控制 | 用户目标 16～30°C；执行目标上下 1°C 迟滞，30 秒最小停机演示保护，温度失效和明确关机立即取消制冷请求 |
| 睡眠／节能 | 两者任一生效时执行目标增加 2°C，最高 30°C；同时启用只增加一次。睡眠风档 1、节能最大风档 2 |
| 风速／强劲 | FAN 循环 1～5，TURBO 请求 5 档；睡眠／节能限制优先于强劲 |
| 统一输出 | PC 与板端都调用 `app_climate_output_mask()`；位 1/2/4/8 分别表示制冷、风机、摆风、灯光请求，关机时全部为 0 |
| 用户界面 | 中文卡片、大号目标、环境与人员健康、模式、执行目标、保护倒计时、策略原因及按钮反馈 |
| 调试界面 | 原有相机／LCD／GPIO／触摸诊断保留在可滚动面板，返回按钮固定可点；指标准确命名为推理更新率 |
| 故障处理 | NN 输入／输出绑定、相机推理管线启动和后处理检查返回状态；已知终止故障不会被在途旧结果覆盖 |
| 相机启动 | 输入等待 5 秒后继续操作；NN 在自身线程分段等待，可以接入晚完成的相机启动，不阻塞本地控制 |
| 共享总线 | 相机与触摸复用硬件 I2C2，通过 ThreadX 优先级继承互斥串行访问，移除触摸对 PD4／PD14 的 GPIO 模拟抢占 |
| 光照驱动 | 初始化和读取检查 HAL 状态，6 次单寄存器读取共享 20ms 软件预算；失败不发布部分或未初始化数据 |
| 触摸故障 | 总线失败释放旧指针，后续成功恢复；手指数改为有效点位数量 |
| 演示工具 | PC 增加 AI／光照／温湿度故障切换、60 倍时间、重置和状态变化 CSV 日志；重置取消旧鼠标手势 |

30 秒保护是软件演示参数，不是实际压缩机设备规格。现有无人策略的 10／30 分钟阈值保持不变。AI 故障暂停人员自动策略，不取消用户已有手动电源选择；温度仍有效时，温控可以继续工作。

## 操作

在 VS Code 打开 `simulator/lvgl-preview.code-workspace`，运行“预览：运行”任务。F5 启动配置仍提供，尚未在用户 VS Code 内实际按键验证。

| 按键 | 效果 |
| --- | --- |
| 0／1 | 无人／有人 |
| D／B | 暗／亮 |
| T／Shift+T | 实际温度增加／降低 |
| H／Shift+H | 湿度增加／降低 |
| C／A／S | AI／光照／温湿度离线与恢复 |
| F | 1×／60× 仿真时间；界面标明 PC 模拟与倍率 |
| R | 重置偏好、模拟数据及故障，并取消当前鼠标手势 |
| Esc／关闭窗口 | 正常退出 |

通过鼠标操作 POWER、MODE、FAN、SLEEP、SWING、ECO、TURBO、TEMP±。先按 POWER，再提高实际温度，可观察制冷请求与等待；按 F 加速验证无人节能与关机。`--duration-ms` 始终按真实经过时间计算。

状态与输出变化时，终端打印 `CLIMATE,时间,原因,request=...`。数据为模拟输入，调试页的测试图不是开发板摄像头画面。

## 仍需完成的项目

需要验证实板的触摸／相机同时运行、持续 ISP 事务、断线恢复、实际界面与启动稳定性。本文上述验证为第一版源码阶段记录；此后两次应用更新均完成 ST-LINK 烧录与全应用回读校验，但仍不能替代实板长时间测试。vendor HAL 另有约 25ms 的 BUSY 等待，20ms 软件预算不是物理总线异常下的绝对硬实时上限。

本工程的 ATK FSBL 使用 XIP，直接读取 `0x70100400` 的应用向量表；应用不需要额外的 STM32 签名头。BIN 应按原有 postbuild 转换为该地址的 HEX，保留配套 FSBL 与模型。此前“还需封装应用启动镜像”的说明已按实际启动源码核实并更正。

真实继电器 GPIO、设备反馈、掉电偏好、检测框、固定场景文件回放、实际功率测量、网络／语音和模型升级仍属于后续阶段。现有输出和温控用于软件演示，不表示这些硬件或扩展功能已经完成。
